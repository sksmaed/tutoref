S11｜編輯本期時程

對應 US-06、Workflow 3（確認時程）。開新期時可能已先設定（見 S1），之後組長仍要能調整。

情境

初驗進行到一半，組長阿凱要把電光、新武兩家的狀況考慮進去，將初驗送件截止往後延兩天；同時補上總驗的兩個截止日。他不小心把總驗送件截止設得比初驗驗收截止還早，系統要當場指出來。

目前遇到的問題

  • 現在可以設定初驗、總驗各兩個截止點，基本功能已經有。
  • #25 沒有檢查先後順序：送件截止晚於驗收截止也能存（Codex 實測重現）。
  • 改動進行中的截止日時，沒有說明會影響哪些家。

三個方案共同的規則

  • 時間一律標示台北時間；「未設定」和「還沒到」要分得出來。
  • 檢查順序：同一輪的送件截止不能晚於驗收截止；總驗送件截止不能早於初驗驗收截止。違反時在該欄位顯示錯誤，不能儲存。
  • 原方案提到各階段的「開始與截止」；目前系統只有截止時間，三個方案都先只畫截止點（簡化），之後要加開始時間再擴充。
  • 逾期不擋（沿用現有規則），只在畫面上標記；改動已經開始的輪次時，確認畫面說明哪些家會受影響。

版面與互動

沿用「本期驗收管理 → 驗收時程」分頁：上方是整期的摘要時間線，下方初驗、總驗各一張表單卡片，直接改日期、在欄位旁即時顯示順序錯誤。按「儲存時程」時，如果改到的是已經開始的輪次，先跳確認說明影響。

優點

  • 一頁同時看得到全期順序與要改的欄位
  • 錯誤就在欄位旁邊，不用猜哪裡錯
  • 現有分頁加上檢查即可，改動小

缺點

  • 日期欄位多，頁面較長
Claude 與 Codex（第三輪）都推薦 A。最重要的是「改得了、順序對、改了立刻生效」；現有分頁補上檢查與影響說明就能做到。這頁是依 Codex 第二輪的要求新增的；第三輪 Codex 確認方向正確，並指出的缺口已補上。

版面與互動

每一輪一張卡片，平常只顯示日期與狀態；按「編輯本輪」開小彈窗，一次只改一輪。儲存時一樣檢查和另一輪的先後關係，有錯就在彈窗內標出。

優點

  • 頁面簡短，不會誤改到沒打算動的那一輪
  • 平常瀏覽時資訊最乾淨

缺點

  • 兩輪都要調整時要開兩次彈窗
  • 改的時候看不到另一輪的日期，比較難對照
如果時程設定好後很少再動、只偶爾延一下某一輪，B 最不容易誤改。

版面與互動

時程分頁顯示月曆，四個截止日是月曆上的事件；旁邊有事件清單。點事件從右側打開抽屜，用表單輸入正確的日期時間（不用拖拉當唯一的輸入方式）。

優點

  • 最容易看出和寒假、營期、考試週有沒有撞到
  • 間隔太短一眼就看得出來

缺點

  • 要做月曆元件，實作成本最高
  • 精準輸入還是要靠表單
如果排時程時最常卡在「跟其他活動撞期」，C 的月曆最直覺；Milestone 1 不一定需要做到這樣。
