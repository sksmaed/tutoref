S3｜成員資訊、歷史紀錄與單人編輯

對應 US-04（點列看成員資訊＋歷史紀錄）與 US-05 的單人編輯、退團處理。

情境

組長點了「陳怡君」，想知道她這期在哪幾家、做什麼角色、以前幾期當過什麼；接著把她 27 冬在新武的撰寫者身份移除（她只留在電光）。另一位成員中途退團，組長要把他本期的角色全部拿掉。

目前遇到的問題

  • C-08 點列沒有反應，只能按「編輯」直接進編輯彈窗；沒有歷史紀錄。
  • C-03 在編輯彈窗改家別，角色不會跟著搬到新家，列表家別變「—」。

需要你決定

US-05 寫「可編輯各期家別與角色」，但 Workflow 1 寫「舊期改為唯讀」，兩者衝突。原型的預設是舊期唯讀：歷史紀錄只能看，只有現行期可以改。如果你們確實需要更正舊期資料，建議改成「需填更正原因」的特殊操作，而不是一般編輯。

版面與互動

點列開啟「成員資訊」彈窗：上半部是基本資料與帳號狀態，下半部是歷史紀錄表格（期別／家別／角色，同期不同家分列）。按「編輯」在同一個彈窗切換成編輯模式：姓名可改、信箱鎖定；家長、撰寫者以「家別＋角色」一列一列編輯，驗收者、教案組長是全期角色另列一行。退團用獨立的「清空本期角色」，和「移除家別身份」是兩個不同動作。

優點

  • 完全照需求：點列 → 彈窗 → 編輯按鈕
  • 歷史表格可以直接檢查「同人同期不同家」
  • 改家別時角色跟著那一列走，從介面上就避免 C-03

缺點

  • 期別很多時彈窗內要捲動
  • 要逐位查看時得一直開關彈窗
Claude 與 Codex（審查後）都推薦 A。把「家別＋角色」綁成同一列編輯，是避免家別和角色分家（C-03）最直接的介面寫法。

版面與互動

點列從右側滑出抽屜，表格仍留在左邊可以看到。抽屜上方是摘要，下方用分頁切換「本期身份」與「歷史紀錄」；頂部有「上一位／下一位」，以成員為單位（陳怡君的兩列只算一位），維持目前的篩選順序。本期身份直接在抽屜內編輯；有未儲存的修改時切換上下位，會先詢問要儲存還是捨棄。

優點

  • 開期後逐人核對名單最快，不用反覆開關
  • 表格還看得到，知道自己在第幾位

缺點

  • 需求寫的是「彈窗」，這是抽屜，要團隊接受
  • 歷史紀錄藏在分頁裡，要多點一下
如果每期開期都要一位一位確認二、三十人，B 的「下一位」會省很多時間。

版面與互動

點列開大彈窗：左欄是個人摘要與帳號狀態，右欄是依期別排列的時間軸，每一期展開後用小表格列出該期的家別與角色（同期不同家分列，預設展開現行期與上一期）。現行期那一段有「編輯本期身份」按鈕，舊期都標唯讀。

優點

  • 長期成員（待過很多期）的經歷最好讀
  • 適合之後延伸「歷年擔任過的職務」

缺點

  • 多一層展開，跨期比較比平面表格慢
  • 彈窗較大，小螢幕要捲動
如果成員資訊之後也想拿來看「這個人當過幾次撰寫者、驗收者」，C 的時間軸比較好延伸。
