Milestone 1 UI 方案 ／ S1

S1｜開始新的一期

對應 US-01、Workflow 1（含 Workflow 2 的「自動複製上一期家別與角色」）。

情境

26 夏結束，組長阿凱要開 27 冬：建立唯一的現行期別，舊期保留但改成唯讀，新期從空白驗收流程開始，並設定初驗與總驗時程。開完之後，組長、驗收者、各家家長與撰寫者要能直接在新期工作。

目前遇到的問題

  • C-01「設定」裡沒有任何開新期的入口，只能打 API。
  • C-02 啟用新期後組長在新期沒有角色，管理頁全部消失，被鎖在外面。
  • C-06 舊期不會自動變唯讀。C-07 角色要手動選期別複製。

三個方案共同的前提

不論選哪個方案，後端都要把「建立新期 → 帶入上一期角色 → 舊期設唯讀 → 切換現行期」當成同一個動作完成，否則還是會重演 C-02 的鎖死問題。風險文案建議從「本期驗收資料將被清空」改為「舊期資料會保留並轉為唯讀，新期從空白驗收流程開始」，避免組長誤以為資料會被刪掉。建立失敗時保留已填的內容並顯示原因，可以直接重試；建立成功後立即更新權限與側欄，並提供「前往成員管理」繼續調整名單。

需要你決定：開新期時要不要一併從上一期帶入驗收標準（初驗／總驗）？成員的家別與角色依 Workflow 2「自動複製上一期」一律帶入、不能取消（包含組長自己），之後在成員管理調整。

版面與互動

使用者選單 → 設定，組長才看得到「期別管理」卡片。按「開始新的一期」開兩步驟彈窗：第 1 步填新期資料與時程（成員家別與角色固定帶入，驗收標準可選）；第 2 步列出切換後會發生的事，確認後按「建立並切換到 27 冬」。

優點

  • 最貼近原需求（設定 → 按鈕 → 彈窗）
  • 先填完再確認，低頻但影響全團的動作不容易誤觸
  • 沿用現有 Dialog，實作量最小

缺點

  • 比一頁式多一步
  • 時程欄位多，彈窗要捲動
Claude 與 Codex（審查後）都推薦 A。開新期一學期只做一次，用兩步驟把「要建立什麼」和「會影響什麼」分開確認，最不容易出錯，又只需要現有元件。第 2 步的「我了解」勾選是原方案沒有的加強，可視情況拿掉。

版面與互動

同一個入口打開大彈窗，左邊填新期資料、時程與帶入選項，右邊即時預覽「切換後會發生什麼」。所有資訊同時可見，底部一顆按鈕完成。

優點

  • 一眼看到全部設定與結果，熟手最快
  • 預覽隨輸入即時更新，比較不會漏看

缺點

  • 資訊密度高，第一次使用比較吃力
  • 小螢幕要上下捲動，預覽會被擠到下面
  • 確認與填寫混在一起，比較容易一路按到底
適合每學期都由同一位熟悉流程的組長操作；如果組長每期換人，A 的分步確認比較保險。

版面與互動 變體：比原方案多了草稿期別與公告

設定裡的「準備下一期」連到一個檢查清單頁。新期先以「準備中（尚未啟用）」建立，組長逐項完成時程、成員、驗收標準，全部必要項目打勾後，最後一步才「啟用 27 冬」，並跳出與 A-2 相同內容的確認彈窗。啟用前全團仍在 26 夏工作。

優點

  • 開期前就能把成員與標準調好，啟用當下大家就能工作
  • 準備期間組長仍在舊期、有完整權限；啟用時系統仍須確認新期已有組長身份，才能避開 C-02
  • 可延伸成每學期的開期 SOP

缺點

  • 多一頁與「準備中」狀態，實作成本最高
  • 成員、標準頁面都要能編輯「尚未啟用的期別」
  • 對 Milestone 1 可能做太多
如果你們希望開期當天就能讓家長、撰寫者直接上傳，C 最完整；只想先解決「開得了期、不被鎖」，A 就夠了。
