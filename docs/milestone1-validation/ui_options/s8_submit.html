S8｜家長送出初驗與鎖定

對應 US-11、Workflow 7：按一個按鈕整批送出整家的待驗收教案與缺交紀錄，鎖定後不能再改檔案。

情境

電光家長準備在截止前送出初驗：2 份教案要送驗、2 份缺交已登記。其中「電光的秘密」雖然已經上傳，但教案紙其實上傳失敗了。家長需要在送出前發現這件事，而不是送出後才由驗收者回報「沒有檔案」。

目前遇到的問題

  • C-05C-20 附件上傳失敗時仍判定「已繳」，確認視窗也沒有提醒，送出的快照裡沒有檔案。
  • C-14 送出後撰寫者仍能透過 API 改名、換投影片（後端要補鎖定檢查）。
  • 全家都還沒上傳教案時，「送出驗收」按鈕不能按，無法只送缺交清單（Codex 發現）。

三個方案共同的規則

  • 按鈕與確認視窗都寫明家別與輪次（「送出電光家初驗」），送出範圍是整家本輪資料。
  • 納入本輪的教案若有附件失敗或還在處理中，不能送出：先重新上傳，或改登記為缺交（不會只是從清單消失）。
  • 0 份教案、只有缺交紀錄時也能送出。送出後，後端要拒絕修改本輪已凍結的內容（名稱、附件、缺交）；總驗的修改版另外建立新版本，不受影響。

版面與互動

家內教案頁底部有一條固定的摘要列：「本輪送出 2 份｜缺交 2 份｜需處理 1 份」。按「送出電光家初驗」開確認彈窗，完整列出要送的教案（含附件狀態）與缺交清單；有需處理的項目時，確認鈕停用並說明原因。送出中按鈕停用、防止重複送出；成功後回到家內教案，顯示送出人與時間（見 S6 畫面 A-2）。

優點

  • 就是現有的送出流程，只補上清單與擋件規則
  • 確認時看得到完整名單，不用心算

缺點

  • 教案很多時彈窗要捲動
  • 要修正問題得先關掉彈窗
Claude 與 Codex（審查後）都推薦 A。現有的確認彈窗方向是對的，主要缺的是「完整清單」和「附件異常時擋下來」。摘要列放在頁底是對原方案（放清單上方）的小幅變體。

版面與互動

「送出驗收」先進入一個核對頁（仍在同一個版面裡）：左邊是要送驗的教案，可以直接開附件預覽；右邊是缺交清單。附件失敗的教案可以「改為缺交」，直接帶到右邊登記，不會只是被排除而消失。最下面固定一條確認列，所有項目都沒問題才能送出，送出後回到家內教案。

優點

  • 一家十幾份教案時，核對最舒服
  • 可以把核對頁連結傳給其他家長一起看

缺點

  • 多一頁、多一次返回
  • 只有兩三份教案時顯得太重
教案份數多的家（例如一輪十份以上）用 B 會比彈窗好核對。

版面與互動

按「檢查送件」打開右側抽屜，逐項列出檢查結果（附件、缺交、截止時間），每個問題都有「前往處理」可跳到對應的列。全部通過後，抽屜底部按「送出」，再跳一個極簡的確認彈窗。

優點

  • 發現問題、修正、再檢查的來回最快
  • 檢查項目之後可以擴充（例如教案時長、類別缺漏）

缺點

  • 抽屜加彈窗兩層；現有 Drawer 按 Esc 會直接關閉，疊彈窗時要先調整元件
  • 概念比 A 多，第一次用的家長要學
如果之後想加更多送件前檢查（例如自動檢查教案紙欄位是否完整），C 的「檢查清單」最好擴充。
