S12｜更新驗收標準

對應 US-07、Workflow 3（確認驗收標準）：按照固定格式編輯標準內容；「匯入教案組企劃書、自動解析標準」是 nice-to-have。

情境

開期後組長從上一期帶入初驗標準 v1，想把「時間安排」類的一個項目改寫、把底分改成 100、門檻改成 94／83／62。初驗任務已經有幾份分配出去了，他要知道改了之後，那些任務用的是哪一版。

目前遇到的問題

  • 固定格式編輯（類別、項目、扣分）、另存新版已經可以用。
  • #24 另存新版只送出底分，原本改過的門檻會被重設成 30／25／20（Codex 實測重現，`RubricEditor.tsx:255`）。
  • 畫面上看不出「已分配的任務用哪一版」，改版的影響範圍不清楚。

三個方案共同的規則

  • 底分與三個門檻都是標準的一部分，另存新版時要完整保留，介面上也要能改。
  • 存檔時說清楚生效範圍：已分配的任務維持原本的版本，之後新分配的任務才用新版（或由組長選擇「全部任務改用新版」，並列出受影響份數）。
  • 企劃書匯入（nice-to-have）只會產生草稿，人工確認後才會成為新版本。

版面與互動

沿用「本期驗收管理 → 驗收標準」的初驗／總驗分頁與現有的逐條編輯器，補上底分與三個門檻欄位；右側即時預覽驗收者會看到的表單。按「建立新版本」時跳確認，寫明生效範圍與受影響的任務數。

優點

  • 就是現有的編輯器，補欄位與確認即可
  • 預覽讓組長知道驗收者實際看到什麼
  • 生效範圍寫清楚，不會悄悄套用到進行中的任務

缺點

  • 項目多時頁面很長
Claude 與 Codex（第三輪）都推薦 A。現有編輯器方向對，主要補「門檻要保留」和「生效範圍要講清楚」。這頁是依 Codex 第二輪的要求新增的；第三輪 Codex 確認方向正確，並指出的缺口已補上。

版面與互動

主畫面是標準的清單表格（類別、檢核項目、扣分、目前版本），點某一項從右側打開抽屜編輯該項的文字與扣分；排序和新增留在清單上。底分與門檻放在清單上方的設定列，同樣在抽屜裡編輯。

優點

  • 項目很多時掃讀最快
  • 一次只改一項，不容易改錯別的

缺點

  • 要大改整段文字時，一項一項開很慢
  • 多次修改要累積成一個新版本，存檔時機要設計
如果每學期只會微調少數幾項，B 的逐項編輯最清楚。

版面與互動

分成「目前使用」與「編輯中的草稿」兩個狀態。草稿可以手動編輯，也可以由「匯入企劃書」自動產生（nice-to-have）；發布前列出和目前版本的差異（新增、刪除、修改的項目與門檻），確認後才成為新版本。

優點

  • 改了什麼、何時生效最清楚，方便追溯
  • 可以直接接上企劃書匯入：匯入只產生草稿，不會直接生效

缺點

  • 需要草稿與發布機制，超出單純的編輯功能
  • Milestone 1 可能用不到這麼完整
如果之後一定會做「匯入企劃書」，C 的草稿＋差異確認是最穩的底子；只想修好現有編輯，A 就夠了。
