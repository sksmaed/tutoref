S5｜新增成員與帳號認領

對應 US-02：只新增一位；TBD 的「匯入通訊錄」與兩種認領方式（①組長建帳號、本人登入後改密碼 ②本人註冊後輸入驗證碼認領身份）。

情境

新加入的隊輔林小安還沒有 Tutoref 帳號。組長要把她加進 27 冬電光家、角色是撰寫者，並且讓她知道怎麼開始登入。另一位舊成員撰寫者小美已經有帳號，只要加進本期即可。

目前遇到的問題

  • C-19 可以用 email 建立「沒有密碼的帳號」，但本人不會收到通知；用同一個 email 註冊會被拒絕，只能自己想到去按「忘記密碼」。
  • 沒有匯入通訊錄，也沒有驗證碼認領。

需要你決定

認領方式要二選一，介面才能寫清楚：①組長建帳號＋本人設定密碼（A、B 採用：系統產生「設定密碼連結」或請本人用「忘記密碼」）；②本人自己註冊＋輸入認領碼（C 採用：組長匯入名單時系統產生認領碼，本人註冊後輸入）。②要改註冊流程（同 email 不能被擋），工程量較大。

版面與互動 假設：設定密碼連結與效期待決定

「＋ 新增成員」開彈窗。輸入 email 後立刻判斷：已有帳號就顯示「加入本期」，沒有帳號就顯示「建立待認領成員」。家別＋角色用和 S3 相同的「一列一個家別」編輯。儲存後彈窗變成完成畫面，提供「複製設定密碼連結」，組長貼到 LINE 給本人即可。還要處理：信箱已在本期、信箱格式錯誤、連結失效時重新產生。

優點

  • 完整滿足「只新增一位」
  • 組長清楚知道對方是新帳號還是舊帳號
  • 不必依賴寄信（目前寄信設定也不穩）

缺點

  • 一次只能加一位，開期大量加人時較慢
  • 後端要新增「產生設定密碼連結」的 API
Claude 與 Codex（審查後）都推薦 A。推薦的是「單人新增＋一條真的能用的認領路徑」；用設定密碼連結只是其中一種做法，選 A 不代表已決定這個機制。匯入名單（C）等格式確定後再做。

版面與互動

「＋ 新增成員」打開右側抽屜，填一位後按「儲存並新增下一位」：個資清空、家別與角色保留，方便連續加同一家的成員。左邊表格即時多出新的一列，新帳號標示「待認領」，每列都能「複製認領資訊」。認領方式同 A。

優點

  • 開期時連續加同一家多人最快
  • 不離開成員表格，加完立刻看得到

缺點

  • 保留上一位的角色，可能誤加錯角色
  • 設定密碼連結要逐位到表格裡複製
如果開期時常常一口氣加十幾位新成員、又還沒有通訊錄格式，B 是 A 和 C 之間的折衷。

版面與互動 變體：把「匯入」和「註冊＋認領碼」綁在一起示範

「新增成員」彈窗分「單筆／匯入名單」兩個分頁。匯入通訊錄 CSV（姓名、信箱、家別、角色）後先逐列預覽：新帳號、已存在、格式錯誤分開標示，只建立有效的列。新帳號各自產生一組認領碼，本人自行註冊後在設定頁輸入認領碼，就會綁上 27 冬的身份。「匯入名單」是輸入方式、「認領碼」是認領機制，兩者可以分開決定（匯入也可以搭配 A 的設定密碼連結）。

優點

  • 開期大量加人最快，也能在建立前抓出錯誤
  • 認領碼不需要組長代管密碼

缺點

  • 要定 CSV 格式、處理重複與部分成功，屬於 TBD 範圍
  • 要改註冊流程與新增「輸入認領碼」頁，工程量最大
TBD 的兩個項目都做的話是 C；建議 Milestone 1 先做 A，C 排到之後的里程碑。
